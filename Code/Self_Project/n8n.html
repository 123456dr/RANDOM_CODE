Project Overview

施工通知書自動派送流程

課程：當機器人來上班－未來職場的 AI 必修課 期末作業｜2026

我在一家正在數位轉型的病媒防治公司當行政工讀生。每位客戶的施工通知書建立好之後，我都要手動歸檔、到官方 LINE 找到客戶傳簽署連結、一直回去看客戶簽了沒、簽完再歸檔一次。這個專案用 n8n 把這段流程自動化，並在我的電腦上用 Ollama 跑一個本地 AI 模型，幫我檢查資料、草擬訊息；但訊息要我在 Discord 按下「核准」才會送出。

一句話流程

我建好通知書，放進「待發送」資料夾 → AI 對照行事曆檢查並草擬訊息 → 我在 Discord 回覆「核准」→ 自動歸檔並傳簽署連結給客戶 → 客戶簽完自動歸檔、回覆客戶並提醒我 → 每天傍晚提醒還沒簽的客戶。

範圍界定：公司的通知書建立系統還沒開放外部串接，所以「看行事曆、輸入資料、建立通知書」這一步維持人工。自動化從通知書建立完成之後開始。因為涉及公司機密，作品中的公司「安心病媒防治」、客戶與施藥人員全部虛構，並用 Google 工具和 Discord 模擬公司的伺服器與官方 LINE。
Part 1

n8n 是什麼

n8n 是一個工作流程自動化工具。你在畫面上把一個個方塊（節點）用線連起來，每個方塊做一件小事，資料就會從左邊流到右邊。不用從頭寫程式，也能把 Google、Discord、AI 模型串在一起。

可以把它想成工廠的流水線：觸發節點是門鈴，門鈴一響，流水線上的每個工人依序處理同一份資料。

六個核心名詞

名詞意思在我的專案裡
Workflow
工作流		一整條流水線，存成一個 JSON 檔流程 A～D 各是一條 workflow
Node
節點		流水線上的一個工人，做一件事「讀試算表」「呼叫 AI」「發 Discord 訊息」
Trigger
觸發節點		流程的起點，決定什麼時候開始跑資料夾有新檔案、Discord 收到訊息、每天 18:00
Item
資料項目		節點之間傳遞的資料，格式是 JSON一位客戶的資料就是一個 item
Expression
運算式		用 {{ }} 取前面節點的資料{{ $json.客戶名稱 }} 會變成「王小明」
Credential
憑證		連到外部服務的帳號授權，存在 n8n 裡Google 帳號、Discord 機器人、Ollama 網址

資料在節點之間長什麼樣子

n8n 裡每個節點的輸出都是 JSON 陣列。下一個節點用運算式拿裡面的值。例如「讀行事曆」節點輸出：

行事曆節點的輸出（JSON）
[
  {
    "客戶編號": "C001",
    "施工日期": "2026-12-01",
    "施工時間": "09:00–11:00",
    "客戶名稱": "王小明（假資料）",
    "施工類別": "白蟻防治",
    "施藥人員": "張師傅"
  }
]

下一個節點寫 {{ $json["施工日期"] }}，執行時就會被換成 2026-12-01。這就是課程 12.5「JSON 概念」在實際流程裡的用法。

Part 2

n8n 怎麼搬到我的電腦上

n8n 有雲端付費版，也可以自己架。我選擇用 Docker 在自己的電腦上架，原因有三個：免費、資料留在我電腦裡、跟課程 12.4 的示範一樣。

Docker 用一個比喻講完

正常安裝 n8n 要先裝 Node.js、對好版本、再裝一堆套件。Docker 的做法是：別人已經把 n8n 和它需要的一切裝進一個便當盒，我只要拿來加熱。

Docker 名詞比喻技術上是什麼
Image 映像檔食譜＋材料包唯讀的打包檔，例如 n8nio/n8n、ollama/ollama，從 Docker Hub 下載
Container 容器正在吃的便當從 image 啟動的程式，有自己的檔案系統與網路，可以開關、刪除
Volume 磁碟區便當盒外的保鮮盒容器外的儲存空間。容器刪掉，資料還在
Port mapping 連接埠對應取餐窗口號碼5678:5678＝電腦的 5678 埠轉到容器的 5678 埠
Compose一張點餐單用一個 YAML 檔描述多個容器，一個指令全部啟動

我的 docker-compose.yml，逐行解讀

Downloads\n8n作業\docker-compose.yml
services:                       # 這張點餐單要開兩個容器
  ollama:                       # 容器 1：本地 AI。這個名字也是它在內部網路的「門牌」
    image: ollama/ollama:latest   # 用哪個映像檔
    ports: ["11434:11434"]       # 電腦:容器，Ollama 的 API 埠
    volumes: ["ollama:/root/.ollama"]  # 下載的模型存進 volume，重開不用重下載

  n8n:                          # 容器 2：自動化流水線
    image: n8nio/n8n:latest
    ports: ["5678:5678"]          # 瀏覽器打 localhost:5678
    volumes: ["./n8n_data:/home/node/.n8n"]  # 我的流程與憑證存在旁邊的資料夾
    environment:
      - GENERIC_TIMEZONE=Asia/Taipei   # 排程用台灣時間
    depends_on: [ollama]          # 先開 Ollama，再開 n8n

volumes:
  ollama:                       # 宣告上面用到的具名 volume
開發紀錄：課程原檔的兩個錯字
課程提供的 yml 直接執行會失敗：./n8n data 中間有空格，Docker 會把它當成兩個參數；depends on 少了底線，Docker 不認得這個欄位。我改成 ./n8n_data 和 depends_on 後才成功啟動。

啟動指令拆解

在 Downloads\n8n作業 資料夾裡執行
docker compose up -d
字意思
docker呼叫 Docker 程式
compose讀「目前資料夾」的 docker-compose.yml
up建立並啟動單子上所有容器；image 不在電腦裡就先下載
-ddetached，在背景執行，終端機視窗可以關

其他常用指令

指令用途
docker compose ps看兩個容器是不是 running
docker compose logs n8n看 n8n 的執行紀錄，出錯時找原因
docker compose down停止並移除容器；volume 和 n8n_data 保留，流程不會不見
docker exec -it ollama ollama pull qwen2.5:3b進到 Ollama 容器裡，下載模型
Part 3

Ollama 與我用的模型

Ollama 是什麼

先分清楚兩個東西：模型是 AI 的大腦檔案，Ollama 是負責把這個大腦跑起來的程式。模型像食譜，Ollama 像廚師。Ollama 會下載模型、載入記憶體，然後開一個 HTTP 服務等別的程式來問問題。

雲端 AI（例如 ChatGPT）

模型在別人公司的伺服器上跑，資料要傳過去，通常按用量付費，需要網路。

Ollama 本地 AI

模型在我自己的電腦上跑，資料不出我的電腦，不收費，下載完模型後可以離線使用。

為什麼可以免費

一、Ollama 是開源軟體。二、有些公司把模型權重公開讓人下載，例如阿里巴巴通義千問團隊的 Qwen 系列。三、運算用的是我自己的電腦和電費，沒有人需要替我付伺服器費用。代價是模型比雲端的小，能力有限，也會吃我電腦的記憶體和 CPU。

為什麼 Ollama 有網址：它是一個 API 服務

Ollama 啟動後會在 11434 埠開一個 HTTP 服務，其他程式送一個請求過去，它就回傳 AI 的答案。這就是課程 12.6 講的 API。我可以自己用指令測試：

送一個請求給 Ollama
curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5:3b",
  "prompt": "用一句話介紹白蟻防治",
  "stream": false
}'
Ollama 的回應（節錄）
{
  "model": "qwen2.5:3b",
  "response": "白蟻防治是透過藥劑與環境處理，防止白蟻蛀蝕建築木材的工作。",
  "done": true
}

回應內容每次會略有不同。n8n 的 Ollama 節點背後做的就是同一件事，只是幫我包成方塊。

我選的模型：qwen2.5:3b

項目規格對專案的意義
開發者阿里巴巴 Qwen 團隊中文訓練資料多，繁體中文輸出穩定
參數量3.09B（約 30.9 億）筆電跑得動；越大越聰明但越慢
層數／注意力頭36 層；GQA，Q 16 個、KV 2 個GQA 讓推論時的記憶體用量較低
上下文長度32,768 tokens一位客戶的資料加提示詞遠遠用不完
Ollama 下載大小約 1.9 GB（量化版）量化是把數字精度降低以縮小檔案，品質略降但能在一般電腦執行
授權Qwen Research License可下載使用於研究與課程作業；若要商用需另看授權條款
為什麼只讓小模型做簡單的事：3B 模型會犯錯，也可能編造資料（課程 1.4 幻覺）。所以我只讓它做兩件事：檢查欄位齊不齊、寫 60 字以內的訊息；而且輸出一定要經過我核准。
Part 4

我怎麼把 n8n 和 Ollama 串起來

關鍵：容器裡的 localhost 不是你的電腦

Docker Compose 會把同一份檔案裡的容器放進同一個內部網路，並用服務名稱當作主機名稱。所以 n8n 要找 Ollama，網址寫 http://ollama:11434。

在 n8n 裡的設定步驟

  1. 建立 Ollama 憑證左側選單 Credentials → 新增 → 搜尋 Ollama → Base URL 填 http://ollama:11434 → 儲存後顯示連線成功
  2. 加入 Basic LLM Chain 節點這是「把提示詞送給語言模型並拿回答案」的節點
  3. 在它底下掛 Ollama Chat Model選剛剛的憑證，模型選 qwen2.5:3b（課程 13.6 教的「換模型」就是改這裡）
  4. 寫提示詞，要求只回傳 JSON這樣下一個節點才能用 {{ $json.完整 }} 判斷要不要停機
提示詞（Prompt）
你是病媒防治公司的行政助理。請檢查以下施工資料是否完整，並草擬給客戶的 LINE 通知。
必要欄位：客戶名稱、施工日期、施工時間、施工類別。
資料：{{ JSON.stringify($json) }}

只回傳 JSON，不要加任何其他文字：
{"完整": true 或 false, "缺漏欄位": "", "草稿": "60 字以內、禮貌的繁體中文。不可編造資料中沒有的內容"}

「不可編造」和「只回傳 JSON」是針對小模型最常出的兩種問題：自己補資料、回答格式跑掉。格式跑掉時，後面的 If 節點會判定為不完整，流程就停下來通知我，不會把壞掉的訊息傳給客戶。

Part 6

治理設計：把課程的原則變成節點

課程第 2 單元提到，治理不是背法條，而是把原則翻成流程裡的具體步驟。我在流程中放了五個：

原則流程中的做法對應
揭露客戶訊息最後固定加上「本訊息由 AI 協助草擬，並經專人確認後發送」2.4 EU AI Act 透明告知、2.8 揭露聲明
把關AI 草稿先送到 #審核區，我回覆「核准」才會發給客戶2.5 人類監督、Human in the Loop
停機行事曆找不到客戶、或 AI 判定資料不完整，流程停止並通知我2.6 停機機制
紀錄試算表記下 AI 檢查結果、審核人、審核時間、發送時間2.3 可歸責、1.3 出事算誰的
最小化只把客戶名稱、日期、時間、類別交給 AI；施藥人員、資料夾 ID 不送2.3 GDPR 資料最小化

為什麼不讓 AI 直接傳給客戶？課程 3.5 提到 automation bias：人容易相信機器的輸出而不檢查。小模型可能把日期寫錯，一旦傳錯，客戶就會在錯的時間等施工人員。所以最後一步一定由人確認。

Part 7

打開 localhost:5678 之後怎麼操作

啟動容器後，瀏覽器打開 http://localhost:5678。以下是從第一次打開到流程能自動執行的順序。n8n 改版很快，按鈕名稱可能和這裡略有不同，以畫面為準。

  1. 建立擁有者帳號（只有第一次）填 email、姓名、密碼。這個帳號只存在你電腦的 n8n_data 資料夾裡，不會上傳。
  2. 進入 Overview 首頁這裡會列出所有 workflow、憑證和執行紀錄。
  3. 先建立憑證（Credentials）依序新增：Ollama（http://ollama:11434）、Google（課程 13.1、13.2 的 OAuth 憑證）、Discord（課程 14.3 的機器人 Token）。先建好，之後加節點時直接選。
  4. Create Workflow，替流程命名例如「流程 A：送審」。
  5. 按畫布中間的 ＋ 加觸發節點搜尋 Google Drive Trigger，選「檔案新增到資料夾」，指定「待發送」資料夾。
  6. 按節點右邊的 ＋ 接下一個節點依照 Part 5 的順序一個一個加。每加一個，就用運算式從前一個節點拿資料。
  7. 測試：Execute step／Execute workflow單獨執行一個節點，打開節點會看到左邊 INPUT、右邊 OUTPUT 的 JSON。輸出不對就在這裡修。
  8. 存檔右上角 Save（或 Ctrl＋S）。
  9. 啟用流程測試都通過後，把右上角的 Active／Publish 打開。啟用後觸發節點才會在背景持續監聽，不需要你一直開著畫面。
  10. 看執行紀錄（Executions）每次自動執行都會留下紀錄，失敗的會標紅。點進去能看到是哪個節點出錯、錯誤訊息是什麼，把這段複製給 AI 協助除錯（課程 14.7）。
容易卡住的三個地方
1. Ollama 憑證填成 localhost → 連不上，改成 http://ollama:11434。
2. 第一次呼叫模型很慢 → 模型要先載入記憶體，第二次就會變快。
3. 流程測試會跑、但平常不會自己跑 → 忘記把流程設為 Active。
Part 8

限制與下一步

目前的限制

建立通知書仍是人工，因為公司系統尚未開放串接。

用 Discord 和 Google 表單模擬官方 LINE 與電子簽署，真實環境需要換成 LINE Messaging API 與公司的簽署系統。

3B 小模型偶爾格式不穩，靠 If 節點停機和人工核准兜底。

如果公司系統建好之後

把觸發點往前移：行事曆新增客戶就自動產生通知書草稿。

Discord 換成官方 LINE 的 Messaging API。

每日提醒升級成週報表，統計每位客戶平均回簽天數（課程 17.5）。

模型規格來源：Qwen2.5-3B 模型卡（Hugging Face）、Qwen2.5 官方介紹；n8n 與 Ollama 的 Docker 架設方式參考 n8n Self-hosted AI Starter Kit 與課程 12.4、13.5。
