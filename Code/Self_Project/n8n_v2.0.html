施工計畫書草稿自動產生

課程：當機器人來上班－未來職場的 AI 必修課 期末作業｜2026

我在一家施工服務公司當行政工讀生。公司系統已經會自動寄送簽署連結、追蹤回簽，但每一份施工計畫書還是要手動填寫：照同一位客戶上一份計畫書抄地址、施作範圍、負責人員、時間；材料和配比還要找「同類型」的舊計畫書。這個專案用 n8n 讀取舊計畫書、照公司規則產生草稿，再由一個書籤小幫手把草稿逐格填進公司系統。最後由人檢查，再按下「生成計畫書」。

專案介紹要解決什麼問題、怎麼解決、怎麼確保不出錯、還有哪些限制。不需要技術背景。 技術介紹網路、Docker、模擬系統、書籤小幫手、n8n 節點、PDF 解析、建置與除錯。照著做就能重現。

專案介紹 · 02

要解決的問題：每份計畫書都要翻舊檔照抄

一開始我想自動化「寄送簽署連結、追蹤回簽、歸檔」，結果到公司打工時發現，公司系統已經補上這些功能：會偵測回簽，首頁會列出已簽署但還沒歸檔的計畫書，也會把一個月內的行程整理成通知單寄給客戶確認。真正剩下、最花時間的，是製作計畫書本身。

老闆教的製作方法

  1. 看行事曆行事曆只寫日期、施作類型、客戶名稱和時間。類型分成 A 類、B 類，以及兩者合併的 A+B 類。
  2. 找同一位客戶的上一份計畫書完全照抄地址、施作範圍、負責人員、施作時間和施作需時。
  3. 找同類型的計畫書材料和配比要照「同類型」的上一份。如果上一份類型不同，就要往前翻，檔名裡有寫類型。
  4. 一格一格填進系統系統只能手動填寫，沒辦法匯入。

為什麼這件事值得自動化

每一步都不難，但是完全照固定規則、每天重複好幾次，而且最容易出錯的地方剛好最危險：類型不同時忘記往前找，把 B 的材料抄到 A 的計畫書。這會直接影響現場施作，比漏存一份檔案嚴重得多。

階段我在做什麼感受改善機會
查看行程從行事曆找到客戶與類型😐 例行複製行程文字交給 n8n
找舊計畫書開客戶資料夾，找上一份和同類型😫 最煩依檔名自動挑選
照抄填表開 PDF，11 個欄位一格一格複製😩 疲累自動組成草稿、逐格填入
生成計畫書檢查後生成、取得連結😟 擔心保留人工檢查與按下生成

自動化的邊界：「判斷要不要生成」留給人。草稿再正確，最後按下「生成計畫書」的一定是人。

專案介紹 · 03

解決方案：n8n 找舊檔組草稿，小幫手填表

核心想法是把老闆的規則交給 n8n，把判斷留給人。公司系統不能改，所以我不碰它，只做一個「坐在旁邊幫忙打字」的小幫手。

公司規則怎麼變成程式

欄位從哪裡來
施作日期與時間、施作類型、客戶名稱、負責人員這次的行程（行程沒寫時間或負責人員，才沿用舊的並加黃框）
客戶編號、施作地址、施作範圍、施作需時、備註同一位客戶最近一份計畫書
材料及配比同一位客戶最近一份同類型計畫書；完全沒有同類型 → 留空，請人填

「最近」只算行程日期以前的計畫書，所以剛生成的新計畫書不會被拿去抄自己。

實際畫面

專案介紹 · 04

把關設計：自動化也要有人負責

自動化最可怕的不是做不到，而是很快地把錯的事做很多次。計畫書錯了會影響現場施作，所以流程裡放了幾道關卡：

原則流程中的做法對應課程
人工把關小幫手只會「填寫」，不會送出；一定要人檢查後自己按「生成計畫書」2.5 人類監督、Human in the Loop
不確定就交給人查無同類型材料、沿用上次備註時，欄位加上黃框並說明原因；材料查不到就留空，不會亂猜2.5 人類監督
停機行程讀不懂、新客戶查無歸檔時，直接停止並說明原因，不產生任何草稿2.6 停機機制
可追溯面板列出每一格抄自哪一份檔案；n8n 的 Executions 保留每次執行的輸入與輸出2.3 可歸責、透明
資料不出公司全部在本機執行，不把客戶資料送到雲端 AI；用固定規則讀檔名和 PDF 文字2.3 隱私、資料最小化
不改原系統小幫手用書籤載入，公司系統一行程式都沒改；拿掉書籤就恢復原狀導入風險控管

為什麼不讓 AI 直接判斷材料？

材料和配比是有安全風險的內容，老闆的規則也很明確（照同類型的上一份）。用固定規則有三個好處：每次結果都一樣、找得到依據、錯了知道錯在哪。生成式 AI 可能「看起來很合理」地編出一個比例，這正是這個場景最不能接受的。所以查不到同類型時，系統選擇留空交給人，不讓 AI 去猜。

錄影時要示範的兩個關卡

  • 2026/12/08 16:30 A 客戶丁 黃先生：材料欄黃框留空，面板寫「查無 A 類型的過往計畫書…請人工填寫」。
  • 2026/12/12 10:00 B 客戶己 李先生：新客戶，小幫手顯示紅字，表單完全不動。

這兩段證明流程「會停、會求助」，而不只是「會跑」。

專案介紹 · 05

限制與未來

這個作業是「模型屋」：結構和動線都是真的，但要真的在公司用，還需要以下幾件事。

目前的限制影響真實環境的做法
模擬系統的欄位名稱是我自己定的小幫手要知道真實表單每一格叫什麼只改 helper.js 最上面的欄位對應，流程不用動
舊計畫書是我產生的 PDF，格式固定真實 PDF 排版不同，切欄位的方式要調整先拿幾份真實 PDF 測試標籤；掃描檔要加文字辨識（OCR）
行程要自己打成一行或複製一次只處理一份行事曆能匯出的話，可以一次產生整個月的草稿清單
都在我自己的電腦別人用不到經主管與 IT 同意後，裝在公司電腦或內部伺服器

可以延伸的方向

  • 規則以外的提醒：例如幼兒園、餐廳等場所的材料限制清單，草稿一碰到就加黃框。
  • 本機 AI 輔助：行程文字格式很亂時，用本機模型（Ollama）先把文字整理成固定格式，資料一樣不出電腦。
  • 數據回饋（課程 17.5）：記錄每份草稿被人工改了哪些欄位，找出最常需要修正的地方。

技術介紹 · 01

網路基礎：網址、HTTP、JSON、跨網站請求

整個專案其實只在做一件事：幾個程式透過網址互相傳資料。先把這一章弄懂，後面每一章都會變簡單。

網址像地址，找到一台電腦上的一個程式；HTTP 像寄信規則，寄出「請求」、收到「回應」，信封上蓋狀態章；JSON 像填好的表格，大家用同一種格式寫資料；API 是給程式用的窗口，不用看畫面，直接拿資料。

拆解一個網址

http://協定
localhost哪一台電腦
:8090哪個程式（埠號）
/客戶甲（總店）/施工計畫書/程式裡的哪個東西
  • localhost 是「我自己這台電腦」（127.0.0.1）。
  • 埠號像分機號碼：8080 計畫書系統、8090 公司伺服器、5678 n8n。
  • 網址只能放英數字，中文會變成 %E6%9E%97… 這種百分比編碼，+ 會變成 %2B。所以檔名 20260520_客戶丙_A+B.pdf 在網址裡是 …P%2BR.pdf。

GET、POST 與狀態碼

意思這個專案裡的例子
GET拿東西n8n 查客戶資料夾、下載舊計畫書 PDF
POST送東西小幫手把行程送給 n8n；計畫書系統把 PDF 上傳到公司伺服器
200成功n8n 回覆草稿
302請改去另一個網址按「生成計畫書」後轉到完成頁
403不准想用 ../ 跳出公司伺服器的資料夾
404找不到n8n 流程沒啟用、資料夾不存在
500對方程式出錯看 docker compose logs

跨網站請求（CORS）：小幫手為什麼能叫 n8n

小幫手在 localhost:8080 的頁面上執行，卻要呼叫 localhost:5678 的 n8n。埠號不同，瀏覽器就當成「不同網站」，基於安全預設不讓網頁讀取別的網站的回應，除非對方在回應中加上：

Access-Control-Allow-Origin: *    ← n8n 的 Respond to Webhook 節點加這個標頭

另外，小幫手刻意用表單格式（application/x-www-form-urlencoded）送出行程，而不是 JSON。這屬於瀏覽器定義的「簡單請求」，不需要先送一次 OPTIONS 預檢，n8n 也會自動把 schedule=… 解析到 body.schedule。

上傳檔案：multipart/form-data

JSON 只能放文字，PDF 是二進位資料。計畫書系統把 PDF 歸檔到公司伺服器時，用 multipart/form-data：一個請求切成好幾段，各放 folder、filename、file，和網頁上的「選擇檔案＋送出」是同一種格式。

技術介紹 · 02

Docker：一個指令把三個程式架起來

Docker 把程式和它需要的一切裝進一個便當盒，到哪台電腦都一樣。Image 是食譜＋材料包，Container 是做好、正在吃的便當，Dockerfile 是手寫食譜，Volume 是吃完還留著的保鮮盒，Compose 是一次點好幾個便當的點餐單。

Downloads\n8n作業_公開版\docker-compose.yml（重點）
services:
  plan-site:                                  # 模擬公司計畫書系統
    build: ./plan-site                       # 照 Dockerfile 自己做
    ports: ["8080:8080"]                     # 電腦的 8080 → 容器的 8080
    volumes: ["./plan_data:/data"]
    environment:
      - FILE_SERVER_URL=http://file-server:8090  # 生成時自動歸檔
      - TZ=CST-8                              # 台灣時間

  file-server:                                # 模擬公司伺服器＋小幫手書籤
    build: ./file-server
    ports: ["8090:8090"]
    volumes: ["./公司伺服器:/srv"]             # 電腦上的資料夾 = 伺服器上的檔案

  n8n:
    image: n8nio/n8n:latest                  # 下載現成的
    ports: ["5678:5678"]
    volumes: ["./n8n_data:/home/node/.n8n"]   # 帳號、流程都存在這
    environment: [GENERIC_TIMEZONE=Asia/Taipei, TZ=Asia/Taipei]
指令用途
docker compose up -d --build --remove-orphans建立並啟動；--build 重做自己寫的 image；--remove-orphans 移除 compose 裡已經沒有的容器（舊的 ollama）
docker compose ps看三個容器是不是 running
docker compose logs file-server看某個容器的紀錄
docker compose down停止並移除容器；掛載的資料夾都保留

容器之間怎麼找到對方

Compose 會替這些服務建立一個私人網路，裡面有內建 DNS：服務名稱就是主機名稱。所以 n8n 下載舊計畫書時寫 http://file-server:8090/…，計畫書系統歸檔時也寫 http://file-server:8090。在容器裡寫 localhost，指的是容器自己。

反過來，瀏覽器不在 Docker 網路裡，只能用 localhost:5678 這種經過 port mapping 的網址。小幫手是在瀏覽器裡執行的，所以它呼叫 n8n 用的是 http://localhost:5678/webhook/plan-draft-public。同一個服務有兩個網址，要看「誰在連」，這是最容易搞混的地方。

容器與虛擬機的差別

虛擬機（像 VMware 裡的 Kali）模擬一整台電腦；容器共用主機的 Linux 核心，靠 namespaces 隔開檔案系統和網路、cgroups 限制資源，所以幾秒就能啟動。Windows 上的 Docker Desktop 會在背景開一台輕量的 Linux（WSL 2）來跑容器。

時區小插曲：容器預設用國際標準時間（UTC），計畫書時間會少 8 小時，所以加了 TZ=CST-8。這種 POSIX 寫法不需要容器裡有時區資料庫，精簡版 image 也能用。

計畫書小幫手：不改系統也能自動填表

公司系統不能改，n8n 也沒辦法直接操作別人的網頁。解法是做一個書籤小工具（bookmarklet）：書籤的網址不是網站，而是一小段 JavaScript。點下去，它就在目前這個頁面載入小幫手的程式。

javascript:(function(){
  var s = document.createElement('script');
  s.src = 'http://localhost:8090/tools/helper.js?t=' + Date.now();   // 每次都抓最新版
  document.body.appendChild(s);
})();

小幫手做的事

  1. 畫出面板放在 Shadow DOM 裡，樣式和公司網頁互不影響。
  2. 送出行程使用者輸入一行行程（例如 2026/12/01 15:00 A 客戶甲 林先生），按按鈕或 Ctrl + Enter，fetch POST 到 n8n。先試正式網址 /webhook/plan-draft-public，回 404 時改試測試網址 /webhook-test/plan-draft-public；兩個都 404 就提示「流程還沒 Publish」。
  3. 逐格「打字」對每個欄位：捲到畫面中間 → 聚焦 → 一個字一個字加進去，每加一個字就送出 input 事件。下拉選單和日期欄直接設值，再送出 change 事件。
  4. 標示與說明把 warn_fields 裡的欄位加黃框，列出 warnings 與每一格的依據。不會按送出鈕。

為什麼要觸發 input／change 事件？

只改 el.value，畫面上看得到字，但很多網站（尤其用 React、Vue 寫的）是靠「事件」才知道使用者輸入了東西。不送事件，網站可能以為欄位還是空的，送出時就被清掉。模擬真人打字並送出事件，是自動填表最穩的做法。

換到真的公司系統只要改一段

// helper.js 最上面
fields: [
  ['customer_id', '[name="customer_id"]', '客戶編號'],   // 草稿欄位, 公司表單上的選擇器, 顯示名稱
  ['address',     '[name="address"]',     '施作地址'],
  …
]

用瀏覽器的「檢查」（F12）看真實表單每一格的 name 或 id，填進第二欄即可，n8n 流程完全不用動。這種設計叫關注點分離：n8n 只負責「內容」，小幫手只負責「填到哪」。

技術介紹 · 06

n8n 基礎：把工作畫成流水線

n8n 是工作流程自動化工具：把一個個節點用線連起來，資料從左流到右。觸發節點是門鈴，門鈴一響，流水線上的工人依序處理同一份資料。

名詞意思在這個專案
Webhook一個專屬網址，有人 POST 進來就啟動流程「收到行程」節點，網址 /webhook/plan-draft-public
Respond to Webhook決定回什麼給呼叫的人「回覆草稿」「回覆無法產生」
Code寫一小段 JavaScript解析行程、挑選參考檔、組合草稿
If條件分岔：true／false 兩條路行程讀得懂？有歸檔嗎？
HTTP Request對任何網址發請求查資料夾、列檔名、下載 PDF
Extract From File把檔案內容轉成文字或資料讀取 PDF 文字
Execution每跑一次留下的紀錄出錯時看哪個節點紅了

資料長什麼樣：items

節點之間傳的是一個陣列，每個元素是一個 item，裡面有 json（一般資料）和 binary（檔案）。大多數節點會對每個 item 各做一次：「挑選參考檔」輸出 2 個 item（最近一份、同類型一份），後面的「下載舊計畫書」就自動下載 2 次，不用自己寫迴圈。

運算式

寫法意思
{{ $json.customer_id }}上一個節點輸出的欄位
{{ encodeURIComponent($json.folders[0]) }}把中文資料夾名稱轉成網址可用的格式
$('解析行程').first().json（Code 節點裡）回頭拿指定節點的輸出
$input.all()（Code 節點裡）這個節點收到的全部 items

Webhook 的兩個網址：測試網址 /webhook-test/… 只有在節點上按 Listen for test event 後收一次；正式網址 /webhook/… 要流程 Publish（啟用）後才有效。

Respond 模式：「收到行程」設成 Using 'Respond to Webhook' Node，代表 n8n 先不回應，等流程跑到 Respond 節點才把結果送回去。小幫手因此能「問一次、拿到完整草稿」。

技術介紹 · 08

讀 PDF 與套規則：三個 Code 節點在做什麼

1. 解析行程：從一行文字讀出五件事

2026/12/01 15:00 A 客戶甲 林先生
└ 日期 ──┘└時間┘└類別┘└客戶┘└負責人員┘

日期  /(\d{4})\s*[\/\-.年]\s*(\d{1,2})\s*[\/\-.月]\s*(\d{1,2})/   → 2026-12-01
類型  /P\s*\+\s*R|A|B/i                                      → A
時間  /([01]?\d|2[0-3])\s*[:：]\s*([0-5]\d)/                     → 15:00
客戶  把上面三樣和星期、符號拿掉，剩下的第 1 個詞                  → 客戶甲
負責人員  剩下的第 2 個詞                                         → 林先生

用正規表示式（regex）描述「長什麼樣子」，所以順序不同、日期寫成 2026-12-01 或 2026年12月1日、多了「（二）」星期都讀得懂。日期、類別、客戶缺一樣，就回 ok:false 並提示格式；時間或負責人員沒寫，則沿用舊計畫書並加黃框。客戶一定要寫在負責人員前面。

2. 找資料夾、挑選參考檔

① 用名稱找大資料夾      客戶甲 → 客戶甲（總店）/施工計畫書
② 每個檔名找出日期與類型  20261101_客戶甲_B.pdf → 20261101、B
   （檔名沒日期就用檔案修改日）
③ 只留「日期 < 行程日期」的，由新到舊排序        ← 不會抄到自己
④ latest = 第一份                               → 20261101_客戶甲_B.pdf
⑤ same   = 第一份「類型 = A」的                 → 20260610_客戶甲_A.pdf
⑥ 兩份不同就輸出 2 個 item，相同就 1 個

8 碼日期（年月日）剛好可以直接用字串比大小："20261101" > "20260610"，不必轉成日期物件。檔名格式只要求「含日期、含類型」，真實公司的命名稍有不同也能用。

3. 組合草稿：依「欄位標籤」切開 PDF 文字

「讀取PDF文字」把 PDF 轉成一大段文字。因為計畫書版面固定，標籤一定照順序出現，所以做法是：依序找到每個標籤的位置，兩個標籤之間的文字就是前一個標籤的內容。

…施作地址範例市東區示範路 210 號 5 樓施作日期2026-11-01施作時間13:30…
     └──────────── 施作地址的內容 ─────────────┘
  • 找下一個標籤時，從上一個標籤之後開始找。「負責人員」也出現在注意事項裡，但那在後面，不會誤抓。
  • 內容裡的換行全部拿掉，因為 PDF 自動換行會把「共 1」和「2 站」拆開。
  • 內容是「—」代表原本空白，當成空字串。

套規則與提醒

情況材料及配比提醒（黃框）
最近一份就是同類型抄最近一份—
最近一份類型不同，前面有同類型抄同類型那份—（依據會寫出是哪一份）
完全沒有同類型留空chemicals：請人工填寫並請主管確認
舊計畫書有備註—note：沿用上次備註，請確認是否仍適用
行程名稱和舊檔不同—customer：請確認
行程沒寫時間—time：沿用舊計畫書時間，請確認
行程沒寫負責人員—worker：沿用舊計畫書的負責人員，請確認
舊檔讀不到某個欄位—該欄位：請人工填寫

除錯就是沿著資料走過的路一站一站檢查：到哪一站還是對的、到哪一站變錯了，問題就在中間。

症狀原因解法

上線考量：要用在真的公司還差什麼

  • 先取得同意：在公司電腦執行程式、讀取客戶資料，都要經過主管和 IT 同意。
  • 欄位對應：用 F12 找出真實表單每一格的 name 或 id，改 helper.js 的 CONFIG.fields。如果公司網頁有內容安全政策（CSP），可能會擋書籤載入外部程式，就要改用瀏覽器擴充功能。
  • PDF 格式：拿 5～10 份真實舊計畫書測試標籤切割；如果是掃描檔，要先做 OCR 文字辨識。
  • 伺服器路徑：真實歸檔區如果是網路磁碟（例如 \\server\客戶資料），要把它掛載給 n8n 讀取，或請 IT 提供讀取用的 API。
  • 權限最小化：n8n 只需要「讀」歸檔區，不需要寫入權限。
  • 資料不出公司：維持全部本機執行；如果要加 AI，用本機模型，不送到雲端。
  • 紀錄：保留 Executions 一段時間，必要時能查出某份計畫書的草稿依據是哪幾份舊檔。
  • 固定版本：n8nio/n8n:latest 改成固定版本號，升級前先測試。
