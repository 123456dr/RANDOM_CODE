遞迴樹有多大？

T(n) > 2n/2 的白話證明（p.8）

T(n) = T(n−1) + T(n−2) + 1 ← 自己 1 個 + 左右兩棵子樹 > 2 · T(n−2) ← 因為 T(n−1) > T(n−2) > 2 · 2 · T(n−4) > 2 · 2 · 2 · T(n−6) …每次 n 少 2，乘一個 2，總共乘 n/2 次 > 2^(n/2)

正式的歸納法證明（p.9）：基底 T(2)=3 > 2¹、T(3)=5 > 2^1.5≈2.83；假設 2 ≤ m < n 都成立；推論 T(n) = T(n−1)+T(n−2)+1 > 2^((n−1)/2) + 2^((n−2)/2) > 2·2^((n−2)/2) = 2^(n/2)。

Ch1 p.12 – p.15

時間複雜度：T(n)、W(n)、B(n)、A(n)

  • p.12分析效率 = 數基本運算（例如比較）做了幾次，寫成輸入大小 n 的函數。
  • p.13陣列加總：不管數字是多少都跑 n 次 → T(n) = n（every-case，每種情況都一樣）。循序搜尋就不是：次數跟 x 在哪裡有關。
  • p.14所以分三種：W(n) 最差、B(n) 最好、A(n) 平均。循序搜尋 W(n) = n（最後一個或不在）、B(n) = 1（第一個）。
  • p.15循序搜尋平均：x 一定在 S 裡時 A(n) = (n+1)/2。

A(n) = (n+1)/2 怎麼來？

x 在第 k 個位置的機率都是 1/n，在第 k 個要比 k 次：

A(n) = 1·(1/n) + 2·(1/n) + … + n·(1/n) = (1 + 2 + … + n) / n = [n(n+1)/2] / n = (n+1)/2

白話：平均要找一半左右。如果 x 有機率 p 在陣列裡、1−p 不在：A(n) = n(1 − p/2) + p/2。代 p = 1 就回到 (n+1)/2。

常見錯誤

「最好情況」是指同樣大小 n 的輸入中最快的那個（x 剛好在第一個），不是「n = 1」。

Ch1 p.16 – p.30

O、Ω、Θ、o：比較誰長得快

  • p.16演算法 A 是 100n、B 是 0.01n²。n > 10000 之後 B 就比 A 慢。n 夠大時，n 一定贏 n²，係數不重要。
  • p.17–18丟掉低次項：0.1n² + n + 100 跟 0.1n² 在 n 很大時幾乎一樣。常見等級：lg n < n < n lg n < n² < n³ < 2ⁿ。要 n lg n 或更好才能處理超大資料。
  • p.19–20big O（上限）：存在 c 和 N，使得 n ≥ N 時 g(n) ≤ c·f(n)。
  • p.21–22Ω（下限）：存在 d 和 N，使得 n ≥ N 時 g(n) ≥ d·f(n)。
  • p.23–25Θ（夾住）：同時是 O 又是 Ω。用反證法證 n ∉ Ω(n²)。
  • p.26–28small o（嚴格比較小）：每一個 c > 0 都找得到 N。n ∈ o(n²)，但 n ∉ o(5n)。
  • p.29–30性質：所有 log 同一級；不同底的指數不同級；n! 比任何指數都慢；係數和低次項都可以丟。

四個符號，用「比大小」記

符號意思（n 夠大以後）像要找什麼
g ∈ O(f)g 不會比 f 的某個倍數大≤存在一組 c、N
g ∈ Ω(f)g 不會比 f 的某個倍數小≥存在一組 d、N
g ∈ Θ(f)兩邊都被夾住，同一級=O 和 Ω 都證
g ∈ o(f)g 比 f 小一整級<每一個 c 都要找得到 N

證明題的套路：寫出定義 → 選 c（或 d）和 N → 驗證不等式。證「不屬於」就用反證法：假設屬於，推出矛盾。

找 c 和 N 的練習器

投影片的證明，考試照這樣寫

證明 n² + 10n ∈ O(n²)（p.20，兩種 c、N 都對）

方法一：取 c = 2、N = 10。當 n ≥ 10，10n ≤ n·n = n²，所以 n² + 10n ≤ n² + n² = 2n²。

方法二：取 c = 11、N = 1。當 n ≥ 1，10n ≤ 10n²，所以 n² + 10n ≤ n² + 10n² = 11n²。

重點：c、N 只要存在一組就好，不用最小。

證明 n ∉ Ω(n²)（p.25，反證法）

假設 n ∈ Ω(n²)，則存在 d > 0 和 N，使得所有 n ≥ N 都有 n ≥ d·n²。

兩邊除以 dn：1/d ≥ n。但當 n > 1/d 時這不成立，跟「所有 n ≥ N 都成立」矛盾。所以 n ∉ Ω(n²)。

證明 n ∈ o(n²)，以及 n ∉ o(5n)（p.27）

n ∈ o(n²)：任意 c > 0，要找 N 讓 n ≤ cn²。兩邊除以 cn：1/c ≤ n。所以取 N ≥ 1/c 就好。c 再小都找得到 → 成立。

n ∉ o(5n)：假設成立，那 c = 1/6 時也要有 N。但 n ≤ (1/6)·5n = (5/6)n 對正整數 n 永遠不成立 → 矛盾。

直覺：n 和 5n 是同一級（Θ），差的只是倍數，所以不是「嚴格小一級」。

p.29 的性質，一次看懂
  • g ∈ O(f) ⇔ f ∈ Ω(g)（我 ≤ 你，就是你 ≥ 我）。
  • log₂n、log₃n、log₁₀n 都是 Θ(lg n)：換底只差一個常數倍。
  • 2ⁿ ∈ o(3ⁿ)：不同底的指數不是同一級（3ⁿ/2ⁿ = 1.5ⁿ 會一直變大）。
  • 完整排序：lg n < n < n lg n < n² < nʲ < nᵏ < aⁿ < bⁿ < n!（k > j > 2，b > a > 1）。
Ch2 p.2、p.13

Divide-and-Conquer 分治法

拿破崙在奧斯特里茲會戰把兵力比他多的敵軍從中間切成兩半，再各個擊破。折筷子也一樣：一把折不斷，一根一根就折斷了。

三步驟

  1. Divide：把大問題切成一個或多個較小、同類型的實例。
  2. Conquer：解決每個小實例。不夠小就繼續遞迴。
  3. Combine：必要時合併小實例的解。

二元搜尋不用合併（只去其中一半）；合併排序要合併。分治法是由上而下 top-down。

Ch2 p.3 – p.6

二元搜尋的遞迴版

  • p.3跟第 1 章一樣的二元搜尋，找 78。
  • p.4演算法 2.1：相等就回傳 mid；x < S[mid] 就 return location(low, mid−1)；否則 return location(mid+1, high)。
  • p.5遞迴要用堆疊（stack）記住暫存的東西，最差深度約 lg n + 1。迴圈版不用維護堆疊，比較快。這種「最後一步才遞迴」叫 tail recursion。
  • p.6最差情況分析：x 比全部都大。n = 16 時 mid = 8，剩右半 8 個。W(n) = W(n/2) + 1，W(1) = 1 → W(n) = ⌊lg n⌋ + 1 ∈ Θ(lg n)。

遞迴式白話

W(n) = W(n/2) + 1 ← 這層比 1 次，剩一半繼續 W(1) = 1 ← 只剩 1 個時比 1 次 W(16) = W(8)+1 = W(4)+2 = W(2)+3 = W(1)+4 = 5 = lg 16 + 1

「n 要除以 2 幾次才變成 1」就是 lg n，再加最後那 1 次。

合併排序 Merge Sort

  • p.7切成兩半（各約 n/2）→ 各自排序（遞迴）→ 合併成一個排好的陣列。
  • p.8合併：兩個排好的陣列，每次比兩邊最前面的，小的先放。
  • p.9例：37 41 19 81 41 25 56 61 49，一直切到剩 1 個，再一路合回來。
  • p.10合併的最差比較次數 W(h, m) = h + m − 1（兩邊交錯，最後才有一邊用完）。

為什麼少 1 次乘法差這麼多？

遞迴下去每一層都少乘一次。8 次的話 T(n) = 8T(n/2) → n³；7 次的話 → nlg 7 = n2.81。n = 1024 時：n³ ≈ 10.7 億，n2.81 ≈ 2.8 億。

規律：T(n) = a·T(n/2) → nlg a。lg 8 = 3、lg 7 ≈ 2.81、lg 4 = 2、lg 3 ≈ 1.58。

Ch2 p.32 – p.33

門檻值，以及什麼時候不能用分治法

最佳門檻值 threshold：問題切到比這個大小還小時，改用簡單的演算法（例如 Strassen 切到夠小就用標準乘法），因為再切下去分治法的額外成本反而更花時間。

不能用分治法的兩種情況（必背）

  1. 大小 n 的問題切成兩個以上、大小還是接近 n 的問題 → 指數時間。例：遞迴費氏數列，F(n) 切成 F(n−1) 和 F(n−2)。
  2. 大小 n 的問題切成將近 n 個大小 n/c 的問題 → nΘ(lg n)。

第一種情況就該改用第 3 章的動態規劃。

第 4 題　(a) 為什麼快速排序在「已排序」的陣列最慢？(b) Strassen 乘法次數的遞迴式和結果？(c) 大整數乘法怎麼從 4 次變 3 次？

答案

(a) pivot 永遠是最小的，每次只分出左邊 0 個、右邊 n−1 個，問題只縮小 1。W(n) = W(n−1) + n−1 = n(n−1)/2。

(b) T(n) = 7T(n/2)，T(1) = 1 → nlg 7 ≈ n2.81。

(c) 算 r = (x+y)(w+z)，則 xz + yw = r − xw − yz；xw、yz 本來就要算，所以只要 xw、yz、r 三次乘法。
