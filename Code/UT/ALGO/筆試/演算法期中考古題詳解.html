第 1 題5%

複雜度由大到小排序

Sort Θ(lg n)、Θ(n)、Θ(n lg n)、Θ(n²)、Θ(2ⁿ) in descending order.
把這五個複雜度由大排到小（越大＝n 變大時越慢）。

數學不好就代一個數字進去比。用 n = 16：

複雜度n = 16 時怎麼算
lg n42 的幾次方是 16？2⁴ = 16，所以是 4
n16就是 16
n lg n6416 × 4
n²25616 × 16
2ⁿ655362 自己乘 16 次

答案

Θ(2ⁿ) > Θ(n²) > Θ(n lg n) > Θ(n) > Θ(lg n)

小陷阱：題目寫 descending（由大到小），但後面那句「f 在左邊，f 最後會落在 g 的下面」其實是「左小右大」，兩句互相矛盾。考場上寫上面這行，再補一句「若依題目定義（左邊較小），順序為 Θ(lg n), Θ(n), Θ(n lg n), Θ(n²), Θ(2ⁿ)」，兩種解讀都拿得到分。

延伸：如果加上 Θ(1)、Θ(n³)、Θ(n!)，要放哪？

完整順序（小到大）：1 < lg n < n < n lg n < n² < n³ < 2ⁿ < n!

口訣：常數 → 對數 → 線性 → n lg n → 多項式 → 指數 → 階乘。

(2) 時間複雜度

第 3 題15%

用 8 個元素的陣列示範二元搜尋

Using an array with eight elements to illustrate binary search: (1) BEST-case for finding the target; (2) WORST-case for finding; (3) WORST-case for NOT finding.
自己編一個 8 個元素的陣列，示範：找到的最好情況、找到的最差情況、找不到的最差情況。

二元搜尋一句話

陣列要先排好序。每次看中間那格：等於就找到；目標比較小就丟掉右半邊；比較大就丟掉左半邊。每比一次，範圍砍一半。

BinarySearch(S[1..n], x):
    low = 1;  high = n
    while (low <= high):
        mid = ⌊(low + high) / 2⌋
        if x == S[mid]:  return mid          // 找到
        else if x < S[mid]:  high = mid − 1  // 去左半
        else:  low = mid + 1                 // 去右半
    return 0                                 // 找不到

為什麼最差情況會選最右邊？

mid 是往下取整數，所以右半邊比左半邊多一個元素（1～3 有 3 個、5～8 有 4 個）。往右走的路比較長，最差情況就出在最右邊。改找 2（比 3 還小）會發現只要 3 次就結束，這就是為什麼不能隨便挑。

變化題：16 個元素的最差情況要比幾次？

lg 16 + 1 = 5 次。每多一倍的元素，只多比 1 次，這就是 Θ(lg n) 很快的原因。

第 4 題15%

用天平找比較重的假幣

(1) 9 coins a～i, one is heavier, a balance scale, only two weighings. (2) n coins (n is a power of 3), log₃ n weighings. Write the algorithm and its time complexity.
(1) 9 枚硬幣有 1 枚比較重，天平只能秤 2 次，怎麼找？(2) 推廣到 n 枚，秤 log₃ n 次。

關鍵想法：一次秤可以分成「三種結果」

天平有三種結果：左重、右重、平衡。所以每秤一次可以把硬幣分成 3 堆，只秤其中 2 堆：

  • 左邊重 → 假幣在左堆
  • 右邊重 → 假幣在右堆
  • 平衡 → 假幣在沒上天平的那堆

每秤一次，範圍變成 1/3。這就是 分治法（divide-and-conquer），而且是「切三份」的版本。

(1) 9 枚硬幣，秤 2 次

  1. 分三堆：{a,b,c}、{d,e,f}、{g,h,i}。
  2. 第 1 次：{a,b,c} 放左、{d,e,f} 放右。左重 → 假幣在 abc；右重 → 在 def；平衡 → 在 ghi。
  3. 假設是 {a,b,c}。第 2 次：a 放左、b 放右。左重 → a；右重 → b；平衡 → c。

任何情況都剛好 2 次。可以畫成一棵「決策樹」，每個節點有三個分支，2 層剛好 3² = 9 個葉子，對應 9 枚硬幣。

(2) n 枚硬幣（n = 3ᵏ）

FindHeavy(C, n):                 // C 是 n 枚硬幣
    if n == 1:  return C 裡唯一那枚
    把 C 平均分成 G1, G2, G3，每堆 n/3 枚
    把 G1 和 G2 放上天平
    if G1 比較重:  return FindHeavy(G1, n/3)
    else if G2 比較重:  return FindHeavy(G2, n/3)
    else:  return FindHeavy(G3, n/3)
遞迴式：T(n) = T(n/3) + 1 , T(1) = 0 展開： T(n) = T(n/9) + 2 = T(n/27) + 3 = … = T(n/3ᵏ) + k 當 n/3ᵏ = 1，也就是 k = log₃ n 時停下 T(n) = log₃ n ∈ Θ(lg n)

白話：每秤一次剩 1/3，問「要除以 3 幾次才會剩 1 枚」，答案就是 log₃ n。例：27 → 9 → 3 → 1，3 次 = log₃ 27。

為什麼 Θ(log₃ n) 可以寫成 Θ(lg n)？

log₃ n = lg n ÷ lg 3，而 lg 3 只是一個常數（約 1.58）。Θ 會忽略常數，所以不管 log 的底數是多少，都算同一級。

第 5 題15%

分治法找最大值和最小值

Write a divide-and-conquer algorithm to find the maximum and minimum in list S (10%). Determine the time complexity (5%).

分治三步驟（每一題分治都這樣講）

  1. Divide 切：把陣列切成左右兩半。
  2. Conquer 解：遞迴找出左半的 (max, min) 和右半的 (max, min)。
  3. Combine 合：max = 兩個 max 比一次；min = 兩個 min 比一次。合併只要 2 次比較。

最小的情況：剩 1 個 → 它自己就是 max 也是 min（0 次比較）；剩 2 個 → 比 1 次。

MaxMin(S, low, high):              // 回傳 (max, min)
    if low == high:                  // 只有 1 個
        return (S[low], S[low])
    if high == low + 1:              // 只有 2 個，比 1 次
        if S[low] > S[high]:  return (S[low], S[high])
        else:                 return (S[high], S[low])
    mid = ⌊(low + high) / 2⌋
    (max1, min1) = MaxMin(S, low, mid)
    (max2, min2) = MaxMin(S, mid + 1, high)
    return ( max(max1, max2), min(min1, min2) )   // 2 次比較

舉例模擬：S = [8, 3, 6, 1, 9, 4, 7, 2]

[8 3 6 1 9 4 7 2] → (9,1) / \ [8 3 6 1] → (8,1) [9 4 7 2] → (9,2) / \ / \ [8 3]→(8,3) [6 1]→(6,1) [9 4]→(9,4) [7 2]→(7,2)

比較次數：最下面 4 組各 1 次 = 4；中間 2 次合併各 2 次 = 4；最上面合併 2 次。共 10 次。

時間複雜度

T(n) = 2T(n/2) + 2 , T(2) = 1 T(4) = 2·1 + 2 = 4 T(8) = 2·4 + 2 = 10 T(16) = 2·10 + 2 = 22 規律：T(n) = 3n/2 − 2 ∈ Θ(n)

不會解遞迴式也沒關係，用「數比較次數」的方式想：

  • 最底下有 n/2 組兩兩比較，每組 1 次 → n/2 次
  • 合併的次數 = n/2 − 1 次（從 n/2 塊合成 1 塊），每次 2 次比較 → n − 2 次
  • 總共 n/2 + n − 2 = 3n/2 − 2。驗算 n = 8：4 + 6 = 10 ✓

加分句

一般「先找 max 再找 min」要 (n−1)+(n−1) = 2n − 2 次比較。分治法只要 3n/2 − 2 次，比較少。兩者都是 Θ(n)，但分治法的常數比較小。

第 6 題20%

公司派對：上司和直屬部下不能同時來

The supervisor relation forms a tree. Each employee has a conviviality rating. An employee and his immediate supervisor cannot both attend. Describe an algorithm to make a guest list that maximizes the sum of ratings (15%). Analyze the running time (5%).
公司組織是一棵樹，每個人有一個「歡樂分數」。有直接上下屬關係的兩個人不能同時出席。要邀請誰，分數總和最大？

關鍵想法：每個人只有「來」和「不來」兩種

對每個人 v 記兩個數字：

  • in(v)：v 有來時，v 和他底下整個部門最多能拿幾分。v 來了，他的直屬部下都不能來。
  • out(v)：v 沒來時，最多能拿幾分。v 沒來，每個部下可以來也可以不來，挑比較大的。
in(v) = v 的分數 + Σ out(c) （c 是 v 的每個直屬部下） out(v) = Σ max( in(c), out(c) ) 樹葉：in = 自己的分數，out = 0 答案：max( in(樹根), out(樹根) )

這就是 動態規劃（DP）：大問題（整間公司）的答案由小問題（每個部門）的答案組成。計算順序必須是先算部下、再算上司（由下往上，後序走訪 post-order）。

這跟 0-1 背包的「拿或不拿」是同一種想法。

每格下方的 in / out 是算出來的值；綠色＝最後邀請的人

由下往上算（考卷就這樣寫）

人分數in = 自己 + Σout(部下)out = Σmax(in, out)
I, J, K, L, G, M, N, O2,11,2,6,8,9,6,7樹葉：in = 自己樹葉：out = 0
E1414 + 0 + 0 = 14max(2,0)+max(11,0) = 13

H33 + 0 + 0 + 0 = 39 + 6 + 7 = 22
C33 + out(G)=0 → 3max(8,0) = 8
B55 + out(E) + out(F) = 5+13+8 = 26max(14,13)+max(4,8) = 14+8 = 22
D1010 + out(H) = 10+22 = 32max(3,22) = 22
A11 + 22 + 8 + 22 = 53max(26,22)+max(3,8)+max(32,22) = 26+8+32 = 66

答案 = max(in(A), out(A)) = max(53, 66) = 66，A（總裁）不來。

找出名單：由上往下回推

規則：上司有來 → 部下一定不來。上司沒來 → 部下看 in 和 out 哪個大，in 大就來。

  • A：out 66 > in 53 → A 不來
  • B：A 沒來，in 26 > out 22 → B 來 → E、F 不來 → E、F 沒來，所以 I、J、K、L 都看自己：in > 0 → I、J、K、L 來
  • C：in 3 < out 8 → C 不來 → G 來
  • D：in 32 > out 22 → D 來 → H 不來 → M、N、O 來

答案

名單 {B, D, G, I, J, K, L, M, N, O}，總分 5+10+8+2+11+2+6+9+6+7 = 66。
驗算：檢查沒有任何一對是直屬關係 ✓（B 的部下 E、F 沒來；D 的部下 H 沒來；G 的上司 C 沒來）。

時間複雜度

每個人只算一次 in 和 out；算的時候每個直屬部下只被看一次（樹有 n − 1 條上下屬關係）。總工作量跟人數成正比 → Θ(n)。回推名單也是每人看一次，Θ(n)。

常見錯誤：「隔一層選一層」

只選第 1、3 層（A、E、F、G、H）或只選第 2、4 層，都不一定最好。例如 E(14) 和 B(5)：B 來的話 E 不能來，但 B 底下的 I、J、K、L 都能來，反而賺更多。所以一定要用 in/out 去比，不能用猜的。

第 7 題20%

矩陣鏈乘法：最佳乘法順序

A₁(10×4), A₂(4×5), A₃(5×20), A₄(20×2), A₅(2×50). Show the optimal order and the number of multiplications.

先懂一件事：兩個矩陣相乘要幾次乘法？

(a×b) 乘 (b×c) 要 a × b × c 次，結果是 a×c 的矩陣。例：A₁(10×4) × A₂(4×5) = 10×4×5 = 200 次，結果是 10×5。

乘法有結合律，先乘哪兩個都可以，但次數差很多。題目要找最省的括號方式。

把維度寫成一排 d₀～d₅（每個矩陣的列數，加最後一個的行數）：

第 8 題20%

Prim 與 Kruskal

(2) 稀疏 vs 稠密

PrimKruskal Θ(m lg m)誰好
(a) 很稀疏：m ≈ n − 1Θ(n²)Θ(n lg n)Kruskal
(b) 很稠密：m ≈ n(n−1)/2Θ(n²)Θ(n² lg n)Prim

答題句子

Prim 的時間只跟點數有關，固定 Θ(n²)。Kruskal 的時間主要花在排序 m 條邊，Θ(m lg m)，跟邊數有關。連通圖的邊數 n − 1 ≤ m ≤ n(n−1)/2。
(a) 稀疏圖 m ≈ n，Kruskal 為 Θ(n lg n) < Θ(n²)，選 Kruskal。
(b) 稠密圖 m ≈ n²，Kruskal 為 Θ(n² lg n) > Θ(n²)，選 Prim。
