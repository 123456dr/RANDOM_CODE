動態規劃 填表特訓

照投影片 98 頁的順序走。這章每個演算法都是「填一張表」：學會看懂每一格的意思、會用遞迴式填格子、會從表格回推答案，就能拿下手寫模擬題。

整章只要記住一句話

DP = 把小問題的答案記在表格裡，由小到大填，大問題直接查表組出來，不重算。

每一題 DP 都照這 5 步寫（拿分公式）

  1. 格子的意思：一句話寫出 M[i][j]（或 A、D、opt）代表什麼。這一步最多人跳過，卻最重要。
  2. 遞迴式：大格子怎麼用小格子算。
  3. 邊界：最小的格子直接填（通常是 0 或 1）。
  4. 填表順序：一列一列、一條對角線一條對角線，或由右下往左上。
  5. 答案＋回推：答案在哪一格，以及怎麼用另一張表（P、R）還原出路徑／括號／樹。
問題格子的意思填表順序答案在複雜度
二項式係數B[i][j] = i 取 j一列一列往下B[n][k]Θ(nk)
FloydD[i][j] = i 到 j 的最短距離（目前允許經過的點）k = 0,1,…，每次整張表更新整張表Θ(n³)
矩陣相乘M[i][j] = Aᵢ 乘到 Aⱼ 最少幾次乘法一條對角線一條對角線M[1][n]Θ(n³)
最佳二元搜尋樹A[i][j] = keyᵢ～keyⱼ 最佳樹的平均搜尋時間一條對角線一條對角線A[1][n]Θ(n³)
售貨員旅行D[vᵢ][A] = 從 vᵢ 經過 A 全部回 v1 的最短長度集合 A 由小到大D[v1][V−{v1}]Θ(n²2ⁿ)
序列對齊opt(i,j) = x[i..] 和 y[j..] 對齊的最小成本由右下往左上opt(0,0)Θ(mn)

p.2 – p.4、p.13

DP 是什麼？跟分治法比

  • p.2分治法（divide-and-conquer）是由上而下 top-down：把問題切小，各自解。像合併排序，切出來的小問題互不相關，所以很有效率。但像費氏數列這種切完會重複出現同樣的小問題，分治法會一直重算，時間指數成長。
  • p.3DP 一樣把問題切小，但會先算小問題、把答案存在陣列裡，是由下而上 bottom-up。
  • p.4做 DP 的兩步：① 寫出遞迴式（大問題怎麼用小問題表示）② 由小到大算上去。
  • p.13總結：分治法是「盲目遞迴」，DP 是「從最小的開始填表」。分治法沒效率時（小問題重複），改用 DP。

用費氏數列看「重算」有多浪費

F(n) = F(n−1) + F(n−2)。用遞迴算 F(5)：

F(5) / \ F(4) F(3) ← F(3) 算了 2 次 / \ / \ F(3) F(2) F(2) F(1) ← F(2) 算了 3 次 / \ F(2) F(1)

DP 做法：開一個陣列，F[0]=0、F[1]=1，然後 F[2]、F[3]、F[4]、F[5] 依序填，每格只算一次。n 項只要 n 次加法。

考題：DP 和分治法的相同與不同？（必背）

相同：都把問題切成較小、性質相同的子問題。

不同：分治法 top-down，子問題各自獨立時有效率，但子問題重複時會一直重算；DP bottom-up，先解最小的子問題並存起來，之後直接查表，所以子問題重複時也有效率。

p.5 – p.12

二項式係數

  • p.5(a+b)ⁿ 展開後的係數，排起來就是巴斯卡三角形：1／1 1／1 2 1／1 3 3 1／1 4 6 4 1…
  • p.6係數公式 (n 取 k) = n! / (k!(n−k)!)。另一個寫法：(n 取 k) = (n−1 取 k−1) + (n−1 取 k)，邊界 k=0 或 k=n 時等於 1。
  • p.7演算法 3.1（分治法）：直接照遞迴式寫。問題是 bin(n−2, k−1) 會被算兩次，越往下重複越多，總共要算 2·(n 取 k) − 1 次，非常慢。
  • p.8–10DP：用陣列 B[i][j] 存 (i 取 j)。B[i][j] = B[i−1][j−1] + B[i−1][j]，一列一列往下填。
  • p.11把遞迴的 return 換成「填陣列」，就從演算法 3.1 變成 DP 演算法 3.2。
  • p.12複雜度：第 i 列只要填到 min(i,k)，總共 Θ(nk)。

白話：每格 = 左上 + 正上

B[i][j] = B[i−1][j−1] + B[i−1][j] 0 < j < i B[i][j] = 1 j = 0 或 j = i

直覺：從 i 個東西挑 j 個，看第 i 個東西「有挑」（剩下從 i−1 個挑 j−1 個）或「沒挑」（從 i−1 個挑 j 個），兩種情況加起來。

為什麼複雜度是 Θ(nk)？（p.12）

第 i 列要填 j = 0 到 min(i,k)，也就是 min(i,k)+1 格：

i : 0 1 2 … k k+1 … n 格數: 1 2 3 … k+1 k+1 … k+1

前面 1+2+…+k = k(k+1)/2；後面 (n−k+1) 列各 k+1 格。加起來 (2n−k+2)(k+1)/2，最大的項是 n·k → Θ(nk)。

p.21 – p.29

Dijkstra（用 Dist／Prior／Decided 三個陣列）

  • p.21三個陣列：Dist[v] 目前已知到 v 的最短距離；Prior[v] 最短路徑上 v 的前一個點；Decided[v] v 的最短距離是否已經確定（1/0）。
  • p.22步驟：① 找 Decided=0 且 Dist 最小的點 i，設 Decided[i]=1 ② 對每個未決定的 w：Dist[w] = min{Dist[w], Dist[i] + Cost[i][w]}，變小就把 Prior[w] 改成 i ③ 重複。
  • p.23–27例題一步一步：v1(1) → v3(3) → v2(4) → v5(5) → v4(8) → v6(9)。
  • p.28整理成一張表：每列是 Decided 集合，每格寫「Dist/Prior」。
  • p.29用 Prior 回推路徑：v6←v5←v3←v1←v0，所以 v0→v1→v3→v5→v6 = 9。

考卷格式（就是 p.28 那張表）

每列寫「Decided 集合」，每格寫「Dist/Prior」，已決定的點寫「–」。最後用 Prior 一路往回追，寫出每個點的路徑。這張表上面的模擬器會自動長出來，可以拿來對答案。

p.30 – p.39

Floyd 演算法（所有點對的最短路徑）

  • p.30從鄰接矩陣開始，一直把矩陣裡的數字變小。時間 O(V³)。
  • p.31k = 0：每一格問「經過 v0 會不會更近？」Cost₀[i][j] = min{Cost[i][j], Cost[i][0] + Cost[0][j]}。例：v1→v2 原本 ∞，經過 v0：1+4 = 5，變成 5/0。
  • p.32–37k = 1, 2, …, 6 依序做。每格寫「距離/經過的點」。
  • p.38最後的表就是任兩點的最短距離。v0→v6 = 9。
  • p.39三層迴圈 k、i、j 各跑 n 次 → T(n) = n³ ∈ Θ(n³)。

白話：一次開放一個「轉運站」

第 k 輪，允許路徑中途經過 vₖ。對每一格 (i,j) 比較兩條路：

原本的路： D[i][j] 經過 vk 的路： D[i][k] + D[k][j] ← 第 k 列的數字 + 第 k 行的數字 取比較小的

手算技巧：第 k 輪時，第 k 列和第 k 行不會變（自己經過自己沒意義），先把它們圈起來；其他每格 = 「同一列在第 k 行的數」+「同一行在第 k 列的數」，跟原本的比。

怎麼用 p（經過的點）還原路徑？

以 v0→v6 為例：P[0][6] = 5 → 中間經過 v5，拆成 v0→v5 和 v5→v6。P[0][5] = 3 → 拆成 v0→v3、v3→v5。P[0][3] = 1 → 拆成 v0→v1、v1→v3。其餘的 p 都是終點本身，表示直接相連。

所以路徑是 v0→v1→v3→v5→v6，長度 1+2+2+4 = 9。

p.40

最佳化原則：什麼時候能用 DP？

解最佳化問題的 DP 三步：① 建立遞迴 ② bottom-up 求出最佳值 ③ bottom-up 建構最佳解（例如用 P 表還原路徑）。

最佳化原則 principle of optimality

一個問題的最佳解裡面，每個子問題的解也一定是那個子問題的最佳解。符合才能用 DP。

  • 最短路徑 ✓：v1→v2→v4 是 v1 到 v4 的最短路，那它的一段 v1→v2 也一定是 v1 到 v2 的最短路（不然換成更短的，整條會更短）。
  • 最長簡單路徑 ✗：v1 到 v4 最長是 v1→v3→v2→v4（1+3+4 = 8）。但它的一段 v1→v3（長度 1）不是 v1 到 v3 的最長路，最長是 v1→v2→v3（1+2 = 3）。子問題的最佳解拼不出大問題的最佳解，所以不能用 DP。

  • p.43暴力法：括號方式 tₙ ≥ 2tₙ₋₁，至少 2ⁿ⁻² 種，指數時間。
  • p.44符合最佳化原則：如果 A₁((((A₂A₃)A₄)A₅)A₆) 最佳，那其中 (A₂A₃)A₄ 也一定是 A₂～A₄ 的最佳順序。
  • p.45例：M[4][6] = min{(A₄A₅)A₆ = 392, A₄(A₅A₆) = 528} = 392。
  • p.46–47遞迴式：M[i][j] = min over i≤k≤j−1 ( M[i][k] + M[k+1][j] + di−1·dk·dj )，M[i][i] = 0。
  • p.48–53一條對角線一條對角線填表，答案 M[1][6] = 348，順序 A₁((((A₂A₃)A₄)A₅)A₆)。
  • p.54複雜度 Σ(n−diagonal)×diagonal = n(n−1)(n+1)/6 ∈ Θ(n³)。

白話：最後一刀切在哪？

不管括號怎麼加，最後一定是「左邊一大塊 × 右邊一大塊」。切在 k，成本 = 左塊 M[i][k] + 右塊 M[k+1][j] + 最後相乘 di−1·dk·dj（前×中×後）。每個 k 都試，取最小。左塊右塊都更短，已經在表裡，直接查。

維度寫成一排 d₀ d₁ … dₙ，Aᵢ 就是 di−1 × di。

考卷格式

① 寫出 d₀～dₙ ② 每條對角線每一格都列出「k = … : … = …」所有候選，圈最小 ③ 畫 M 表（可以寫成「次數/k」，等於把 P 表合在一起）④ 用 k 由外往內還原括號 ⑤ 照括號順序實際乘一次驗算。

p.55 – p.61

樹的名詞（為最佳二元搜尋樹暖身）

名詞意思
樹沒有環的連通圖（有環或不連通都不是樹）
有根樹指定一個點當樹根，畫在最上面，像公司組織圖
內部節點／外部節點有子樹的／沒有子樹的（樹葉）
父、子、兄弟節點上一層、下一層、同一個父親
level 與 depth投影片樹根是 level 1、depth 0，往下各加 1（兩者差 1，看清楚題目用哪個）
二元樹每個節點最多 2 個子節點（左子樹、右子樹）
二元搜尋樹 BST每個節點：左子樹所有 key 都比它小，右子樹所有 key 都比它大
平衡左右子樹深度相差不超過 1

在 BST 找一個 key 的比較次數 = depth + 1（樹根就要比 1 次）。

p.62 – p.74

最佳二元搜尋樹

  • p.62每個 key 被搜尋的機率是 pᵢ，搜尋它要比 cᵢ 次（= depth+1）。目標：讓平均搜尋時間 Σ cᵢ·pᵢ 最小。
  • p.633 個 key，p = 0.7, 0.2, 0.1，5 種樹分別是 2.6、2.1、1.8、1.5、1.4。最好的是 key1 當樹根、一路往右長（1.4）。最常被搜的要靠近樹根。
  • p.64暴力法要試的樹太多（指數），改用 DP。A[i][j] = keyᵢ～keyⱼ 最佳樹的平均搜尋時間。
  • p.65符合最佳化原則：最佳樹的每個子樹，對它自己的 key 也必須最佳。例：A[2][3] = min{0.4, 0.5} = 0.4。
  • p.66keyₖ 當樹根：左子樹 1～k−1，右子樹 k+1～n。子樹裡每個 key 都多了一層（多比一次），所以要加上它們的機率。
  • p.67–72遞迴式與填表，例題 4 個 key，p = 3/8, 3/8, 1/8, 1/8，答案 A[1][4] = 14/8，樹根 key2。
  • p.73用樹根表 R 由上往下還原樹：2 當根 → 左邊 1；右邊 3～4 的根是 3 → 3 的右邊是 4。
  • p.74複雜度 n(n−1)(n+4)/6 ∈ Θ(n³)。

核心公式

A[i][j] = min over i≤k≤j ( A[i][k−1] + A[k+1][j] ) + (pᵢ + … + pⱼ) A[i][i−1] = 0 , A[j+1][j] = 0 , A[i][i] = pᵢ

白話：試每個 key 當樹根。左邊那群和右邊那群各自用最佳的樹（查表）。為什麼還要加 pᵢ+…+pⱼ？因為整群裡每個 key 都要先跟樹根比一次，所以每個 key 的比較次數都 +1，平均時間就多了它們的機率總和。

跟矩陣相乘長得很像。差別：矩陣是「切在 k 和 k+1 之間」，這裡是「k 本身當樹根」，左右兩邊都不包含 k。

p.63 的 5 棵樹怎麼算？

平均時間 = Σ (比較次數 × 機率)。比較次數 = 那個 key 在第幾層。

(1) key3 根, key2, key1 一路往左： 0.7×3 + 0.2×2 + 0.1×1 = 2.6 (2) key3 根, key1, key2： 0.7×2 + 0.2×3 + 0.1×1 = 2.1 (3) key2 根, 左 key1、右 key3： 0.7×2 + 0.2×1 + 0.1×2 = 1.8 (4) key1 根, key3, key2： 0.7×1 + 0.2×3 + 0.1×2 = 1.5 (5) key1 根, key2, key3 一路往右： 0.7×1 + 0.2×2 + 0.1×3 = 1.4 ← 最小

注意 (3) 是「平衡」的樹，卻不是最好的，因為 key1 被搜的機率高達 0.7，應該放在樹根。

p.75 – p.86

售貨員旅行問題（TSP）

  • p.75從家鄉出發，每座城市剛好拜訪一次，再回到家鄉（漢米爾頓迴路），總長度最短。圖是有向的（單行道）。
  • p.76從 v1 出發，三條旅程長度 22、26、21，最佳是 21。
  • p.77暴力法：第一站 n−1 種、第二站 n−2 種…共 (n−1)! 條路線。
  • p.78符合最佳化原則：最佳旅程 v1→v3→…中，「從 v3 出發走完剩下的點回 v1」那段也一定最短。
  • p.79–80定義 D[vᵢ][A] = 從 vᵢ 出發，經過集合 A 裡每個點一次，回到 v1 的最短長度。
  • p.81–85集合由小到大填表：|A|=0 → 1 → 2 → 3。答案 D[v1][{v2,v3,v4}] = 21，路線 v1→v3→v4→v2→v1。
  • p.86複雜度 Θ(n²2ⁿ)。比 (n−1)! 好很多，但仍是指數。

核心公式

D[vᵢ][A] = min over vⱼ∈A ( W[i][j] + D[vⱼ][A − {vⱼ}] ) D[vᵢ][∅] = W[i][1] （沒地方要去了，直接回家） 答案 = D[v1][V − {v1}]

白話：站在 vᵢ，還要去 A 裡的城市。下一站試每一個 vⱼ：先走 W[i][j] 到 vⱼ，剩下的路「從 vⱼ 走完 A−{vⱼ} 回家」已經算好了，查表。

小提醒

  • W 矩陣是有向的：W[v2][v1] = 1 但 W[v1][v2] = 2，別看反了。看列是「從」，看行是「到」。
  • p.86 投影片最後寫 (n−1)(n−2)2ⁿ⁻¹；用 n = 4 實際加總 Σ 會得到 12 = (3)(2)2¹，所以正確應該是 (n−1)(n−2)2ⁿ⁻³。不管哪個，結論都是 Θ(n²2ⁿ)。考試寫 Θ(n²2ⁿ) 就安全。

三種選擇

opt(i,j) = min( opt(i+1, j+1) + penalty , ↘ x[i] 對 y[j]（相同 0、不同 1） opt(i, j+1) + 2 , → y[j] 對 gap（x 這格空著） opt(i+1, j ) + 2 ) ↓ x[i] 對 gap（y 這格空著） 邊界：opt(m, j) = 2(n−j) , opt(i, n) = 2(m−i)

白話：看兩條序列的「第一個字」。要嘛兩個字對在一起，要嘛其中一個先對空格。剩下的部分已經算好了（右邊、下面、右下的格子），查表加上這一步的罰分。

第 6 題（觀念）　(a) 為什麼最長簡單路徑不能用 DP？(b) 矩陣相乘為什麼不用暴力法？(c) Floyd 和 Dijkstra 各用什麼策略？

答案

(a) 不符合最佳化原則：最長路徑的一段不一定是那段的最長路徑（p.40 的例子）。

(b) 括號方式至少 2ⁿ⁻² 種，指數時間；DP 只要 Θ(n³)。

(c) Floyd 是動態規劃，Θ(n³)，求所有點對；Dijkstra 是貪婪，Θ(n²)，求單一起點。
